# Wine 11.20 D3DMetal (GPTK 4.0b3)

[한국어](README.ko.md)

Yaagl runtime source for Apple Silicon and Rosetta 2, targeting GPTK 4.0 beta 3 exclusively. Wine host, msync, input, media, audio, window and resource fixes are retained. The native sidecar supplies display routing, video-memory policy and FSR-to-MetalFX translation. GPTK's native caches remain responsible for shader, library, PSO and RT function reuse.

DLSS uses Apple's stock `nvngx-on-metalfx.dll` and Unix module. This tree does not include the experimental DLSS translator, Streamline interception or NPC-nameplate composition. No nameplate fix is claimed.

## Current source and patch policy

This tree starts at the official `wine-11.20` tag and ports the selected runtime changes from verified source `1846c16674b`. The Wine sources in `dlls/`, `server/` and `include/` are the build inputs. See [the migration record](documentation/WINE-REBASE.md) for retained contracts and upstream overlap decisions. Historical P3/tuned patch queues remain in the source commit as reference material; they are not reapplied or copied into this tree.

`d3dmetal-sidecar/layout.json` defines the beta3 hook contract: format 32, marker `YAAGLB3SIDEcar\x20`, 27 compact dispatch slots and no additional `binaryPatches`. The first four hooks remain `GetContainingOutput`, `SetFullscreenState`, `QueryVideoMemoryInfo` and `ReplayTemporalScale`. Twelve async gates cover graphics PSO construction/lookup/destruction, MPL direct/indexed draws, root-signature lifetime, command-list reset/query/lifetime and presentation. Five DX11 gates cover direct/indexed draw, query Begin/End and context destruction. `CompleteExecute` retires completed FSR executions, followed by the `PresentResidencyAdd` call-site gate. Four latency gates follow: native NVAPI resolution, Present completion, swapchain destruction and device destruction. `ngx-hooks.mm` dispatches recorded FSR commands through `ReplayTemporalScale`; other commands use Apple's original replay. FSR SR/FG uses the Metal4/MPL transport.

`PresentResidencyAdd` replaces only `DoPresent`'s layer-set registration at `0x16d242`. The inspected macOS 27 IOGPU implementation retains registrations in an `NSCountedSet` and checks the 32-unique-set limit. A queue now registers its current layer set once; a different set removes the previous registration before adding the new one. Other queue registrations remain untouched. The native worker serializes these calls, and queue-associated bookkeeping retains at most one layer set until replacement or queue destruction. This repairs registration accumulation across layer changes, not a demonstrated game-memory spike. `node --test scripts/test-present-residency.mjs` runs the generated x86 call/gate/trampoline and production hook with real Foundation counting/ownership over 128 layer changes, without loading D3DMetal or executing GPU work.

The current Wine FSR entrypoints and native regression callers select Metal4; no in-repository caller selects the backend's Legacy command mode. The SR C++ interface still accepts Legacy with an ordinary `MTLCommandBuffer`, and the sidecar exports its C++ factory/encode symbols, so repository usage alone does not prove external callers absent. Legacy is retained pending an explicit interface cutover. It is separate from AMD native-provider passthrough: `YAAGL_FSR_UPSCALER=native` and FG native fallback do not select MetalFX Legacy.

The old custom PSO/function caches, RT provenance tracking, cache-context hooks and library singleflight remain removed. `GetRenderPipelineState` now has an asynchronous scheduling wrapper, not a replacement cache: Apple's original getter compiles and owns every Metal PSO. The former device-destructor site is used only to retire latency state before calling the original destructor; the other former cache entrypoints remain pristine. Native GPTK shader/stage and disk caches, library publication/reuse, owner-local graphics/compute PSOs and RT function reuse remain in place.

DXGI video-memory queries, containing-output queries, fullscreen entry points and output enumeration use the Windows x64 calling convention, including calls back to the original methods. Native helper methods retain the host ABI. Mixing these conventions causes Unity startup crashes before rendering.

The converter stays pristine. The preparation pipeline runs `native-sidecar-patch`, `native-sidecar-module`, then `final-framework-reseal`. The sidecar lives in `d3dmetal-sidecar/`, is built by `scripts/build-d3dmetal-sidecar.mjs` as `libD3DMetalSidecar.dylib`, and uses `scripts/d3dmetal-sidecar-patch.mjs` for patching. Packaging uses `--sidecar-module` and `--sidecar-manifest`, manifest fields `nativeSidecarBuild` and `nativeSidecar`, and recipe field `patches.nativeSidecar`. These names replace the cache-era interfaces without compatibility aliases; the internal C++ namespace `yaagl::pso` and public FSR C APIs remain unchanged. Excluded patches have different reasons:

| Excluded patch | Reason for the current policy |
|---|---|
| FP64 codec recipe | The known failing codec fixture compiles with the stock beta3 converter, and its cast implementation differs from the old recipe. This does not establish correctness for every FP64/constrained-cast input. |
| Stage-lock and compute-loser cleanup | Beta3 `CompileCompute` already holds the stage-cache lock and releases a duplicate allocation. |
| CacheFile close/munmap | Beta3 closes the file, unmaps the payload and header, and resets its state. |
| CacheFile publication-order | The reader rejects incomplete records and closes or reopens the cache. No reproduced correctness or cache-reuse failure justifies changing the writer order in the default configuration. |
| Legacy fullscreen null/forward call sites | Beta3 forwards the native output itself. Yaagl monitor routing remains a separate sidecar responsibility. |
| Per-frame present-residency removal | The call-site hook instead keeps one current layer set per queue and replaces it only when the set changes, avoiding duplicate counted registrations and preserving the queue's baseline sets. |
| Persistent-cache read-ahead | File warmup is not shader compilation. The game and D3DMetal own shader/PSO precompilation and their on-disk caches. |
| Custom DLSS/Streamline processing | This runtime uses the stock NGX pair; experimental nameplate processing is outside its scope. |

Cursor handling uses the current `cocoa_app.m` and `cocoa_warpconsumption.h` implementation. These policies should not be described as identical to every change in a separate runtime branch.

## Opt-in asynchronous graphics pipelines

Only emitted, nonempty draws update attachment recurrence. DX11 and DX12 omissions do not extend the five-epoch history: if no real draw refreshes a target, its eligibility expires and the next draw takes the native synchronous path. Zero vertex/index or instance counts bypass the DX12 async gate without requesting work or recording target use.

DX12 synchronous requests and owner-wide drains claim unstarted jobs and compile them on the caller instead of waiting for GCD admission. Already running jobs are joined, and every owner variant still completes before native destruction. Each queued callback owns an independent claim token and checks it before touching the state or native PSO, so a callback delivered after assisted completion and destruction cannot compile twice or access the retired owner. Compiler queue width and QoS remain under the existing GCD policy; expanding the ready-ticket cache was not retained because measured multi-PSO misses regressed.

For the pinned native FFX presenter, the PE composition callback carries its context-lifetime identity, frame ID and generated/real flag to the next same-thread, matching underlying Present. A successful generated member followed by the real member of that same frame advances the shared epoch only once. Generated-only and real-only frames still advance; failed, TEST and nonadvancing calls do not. Generated-only mode is captured in the immutable binding and never leaves a pending pair. No-notify configurations preserve the binding still installed on the swapchain. The native callback order is verified against the DLL's RSDS build identity and default-composition entry bytes. Both application callbacks and the original native default UI composition retain their descriptor, premultiplied-alpha extension and user-context semantics. Unknown native builds keep their original behavior. The five-epoch threshold and expiry rules are unchanged; independent real-presenting swapchains still share the existing global clock.

Set `YAAGL_D3DMETAL_ASYNC=1` in the runtime launcher's environment to enable DX12 background graphics PSO compilation and DX11 draw omission while native compilation is pending. The default is disabled. `YAAGL_D3DMETAL_ASYNC_LOG=1` additionally reports operations, including `dx11-skipped`. The read-only native `yaagl_d3dmetal_async_stats` export uses the versioned structure in `d3dmetal-sidecar/async-pipeline.hpp`: queued/ready/failed/synchronous count sidecar-managed DX12 requests, while skipped includes both APIs. These are not driver cache-miss or frame-time measurements.

For DX12, an unready pipeline may omit an MPL `DrawInstanced` or `DrawIndexedInstanced` only on a reset, tracked direct command list with no active query, no geometry/tessellation/mesh/stream-output path, a matching root signature that cannot expose UAVs or directly indexed descriptor heaps, and recurring texture/mip/slice attachments used across five consecutive presentation epochs. Dirty render state is preserved when a draw is omitted, so a later draw binds the completed pipeline normally. Unknown root representations, first-use targets and unsafe paths wait for compilation instead. DX12 `ExecuteIndirect`, mesh, legacy command encoding, compute and RT execution are not skipped.

DX11 reuses beta3's existing background compiler and its atomic outstanding-job flag. `Draw`, `DrawIndexed` and their instanced forms, including deferred command-list replay, may omit only the native draw command while compilation is pending. Native context locking, binding commands and resource tracking remain in their original order. Active queries, predication, bound graphics UAVs, geometry/tessellation/stream-output paths and first-use attachments take the original draw path. Native texture-view/subresource identities must recur across five consecutive Present epochs. A clear outstanding-job flag does not prove that every dynamic variant exists: unscheduled variants, indirect draws and `DrawAuto` retain native compilation behavior rather than being skipped indefinitely.

Expired subresource history is pruned once per texture per Present epoch. DX11 and DX12 history observations use texture-local locks rather than the runtime registry lock. A thread-local memo avoids repeating an already completed attachment-batch observation in the same epoch; it checks freshly resolved history identities, exact subresource keys and atomic mutation revisions without retaining textures. Another thread's history reset, texture address reuse or a new epoch forces a fresh observation. Cold-draw eligibility still checks all attachments under ordered history locks, and the 64-entry reset and texture-owned lifetime rules remain intact.

DX12 draws with an exact ready dynamic key and no outstanding owner work bypass omission-eligibility checks, but still execute native drawing and record target history for later cold PSOs. A thread-local positive ready ticket avoids repeated registry and owner-state locks; admitting any new owner variant or stopping the owner invalidates that ticket before work starts or the native PSO is released. Pending owners retain the full safety checks and unsafe-draw owner drain. DX11-only processes bypass the common getter's DX12 owner-map lock until the first managed DX12 PSO is published; this publication flag never resets during retirement, so mixed-API processes retain normal owner lookup.

The DX12 path uses the native converter to parse the original root signature; eligibility does not assume that an empty shader binding mask proves the absence of UAV writes. Shader translation, function loading and reflection remain synchronous. Sidecar-managed DX12 jobs start only after the graphics constructor finishes and are drained before its native destructor releases the PSO; DX11 keeps the native job and destructor-wait protocol. Cold DX12 draw eligibility retains the pipeline owner in the same locked lookup, avoiding a second runtime-lock acquisition and pipeline lookup without caching eligibility across draws. Existing caches continue to own pipeline results. This is lossy graphics scheduling: eligible objects can appear late, and target recurrence is a heuristic rather than a proof that every render dependency tolerates a missing draw.

`node --test scripts/test-async-pipeline.mjs` exercises deterministic single-flight, pending/ready/failure, retirement, dynamic-key and eligibility behavior, including production texture-history expiry, mip/slice isolation, object lifetime and capacity boundaries. `scripts/d3dmetal-async-smoke.cpp` exercises public D3D12 drawing and GPU readback in a disposable staged runtime, including query and UAV fallback, indirect root-state reset and PSO retirement. Build it with `x86_64-w64-mingw32-g++ -std=c++17 -O2 -static scripts/d3dmetal-async-smoke.cpp -o d3dmetal-async-smoke.exe -ld3d12 -ldxgi -ld3dcompiler -lole32 -luuid`, then run with async disabled and enabled in the same isolated prefix. The smoke accepts an immediately ready first draw; deterministic pending behavior is covered by the native tests without sleeps or compiler timing assumptions.

`scripts/d3dmetal-dx11-async-smoke.cpp` covers public DX11 GPU readback, multithread-protected context locking, all four direct draw forms, query/UAV fallback, first-use targets and deferred replay with retained resources and state restoration. Build with `x86_64-w64-mingw32-clang++ -std=c++17 -O2 -static scripts/d3dmetal-dx11-async-smoke.cpp -o d3dmetal-dx11-async-smoke.exe -ld3d11 -ldxgi -ld3dcompiler -lole32 -luuid -luser32` and run with async disabled and enabled. Native tests hold the pending flag explicitly to check omission, completion, unscheduled-variant progress and safety boundaries without depending on compiler timing.

## Opt-in two-frame latency modes

Set `YAAGL_D3DMETAL_LOW_LATENCY=1` and enable the game's Reflex low-latency option. The default is off and this option is independent of async compilation. It uses the stock NVAPI/Unix bridge and waits in `NvAPI_D3D_Sleep`, which the game must call before sampling input. It does not inject an input hook into games without that call.

Set `YAAGL_D3DMETAL_LOW_LATENCY=force` to enable the two-frame limit without Reflex calls. After a successful advancing Present, it waits for fewer than two unfinished Presents before returning, leaving room for the next frame. The native Present lock has already been released. TEST, nonadvancing and `DXGI_PRESENT_DO_NOT_WAIT` calls do not acquire this additional wait. Native waitable-object settings and swapchain creation flags are unchanged.

Force mode transfers pacing to the input-before-render path only when the game requests low latency and actually calls Sleep. A setting alone does not transfer ownership. If Sleep stops accompanying Presents, or the game turns Reflex off, it resumes forced Present pacing. The two paths never wait simultaneously. Turning Reflex off therefore does not disable an explicitly selected force mode; unset the environment variable to disable it. Force mode cannot locate an arbitrary game's input sampling or prevent a separate simulation thread from running ahead.

In the cooperative path, the limiter admits at most two frames across CPU reservations and unfinished native Presents. Reserving at Sleep prevents a delayed render thread from allowing unlimited CPU runahead. Native Present completion releases capacity; TEST and nonadvancing Presents do not consume it. No extra wait is inserted into cooperative Present.

A TEST followed by a real Present preserves admission. A TEST-only input iteration, or TEST with multiple unidentifiable CPU reservations, disables pacing instead of waiting for a GPU completion that will never arrive.

Both modes suspend pacing for multiple live swapchains and disable it for known FFX-generated frames, out-of-band Reflex markers or overlapping Presents. Cooperative-only mode also disables it for unmatched Presents after admission synchronization. These safety exclusions take precedence over force mode. Ownership changes, exclusions and native retirement wake the affected waiters. Boost is accepted as a hint but does not change Apple GPU clocks. Nonzero NVAPI minimum-frame-interval requests return `NVAPI_NOT_SUPPORTED`; this fixed-depth mode is not an FPS limiter. Sleep status reports effective eligibility and observed Sleep duration; `GetLatency` remains the stock implementation, not a new input-to-photon measurement.

`node --test scripts/test-low-latency.mjs` checks the two-frame boundary, delayed submission, callback-before-return, rollback, forced/Reflex ownership transitions, nonblocking Present, cancellation, retirement and device isolation with event-driven synchronization. See [the latency investigation and implementation notes](documentation/LOW-LATENCY-DESIGN.md) for the native ABI/lifetime evidence and measurement boundaries.

## Build Wine and the sidecar

Maintainers need Xcode, Node.js, Python, LLVM MinGW, Bison and x86_64 TLS/font/media dependencies. Set `WINE_DEPS_ENV` to the dependency environment and `WINE_MINGW_ROOT` to the installed LLVM MinGW toolchain. The build consumes this worktree, including local changes, rather than fetching a different source checkout.

```sh
WINE_NATIVE_SERVER=yes scripts/build-wine-p3.sh all
node scripts/build-d3dmetal-sidecar.mjs build/native-sidecar
```

`WINE_P3_ROOT` selects a fresh build directory; the default is `build/wine-p3-current`. Its `host/` and provenance describe the actual Wine source. Sidecar output includes the dylib and a source-hash manifest. Existing build directories are not evidence that current sources were built.

The staged runtime summary derives its actual hook count from `native_build_manifest.d3dmetal.hookCount`.

### ZZZ Game Mode session

The full-source build uses `scripts/game-mode.py` to compile a standalone universal `game-policy-supervisor` from `scripts/game-policy-supervisor.c` and copy the original Apple-signed `gamepolicyctl`. Both helpers remain in `libexec/yaagl-game-mode/`, outside `ZZZ.app`. The internal x86_64 host reuses the selected build's Wine `loader/main.o` and generated link recipe, embedding `scripts/yaagl-game-mode.plist` and installing the same metadata as the bundle's `Info.plist`. Install signs the supervisor and host bundle separately, without deep signing or modifying the Apple tool. Staging validates signatures, architecture, metadata and the absence of adjacent `ntdll.so`, and inventories the final files. Local and framework-free package manifests require `gameMode: {"version":3,"target":"zzz","supervisor":"libexec/yaagl-game-mode/game-policy-supervisor","host":"libexec/yaagl-game-mode/ZZZ.app/Contents/MacOS/wine"}`; versions 1 and 2 are not compatible.

The launcher opt-in is for ZZZ on Apple Silicon/macOS 26 or later. It starts `game-policy-supervisor <absolute wineserver> <absolute Wine loader> [Wine args...]`, preserving the game environment and standard streams. The normal renderer wrapper remains in the launch path. Off uses ordinary Wine without forcing macOS policy off.

Only an opted-in game launch sets `YAAGL_GAME_MODE_TARGET` to the absolute Unix game EXE path; setup commands do not. Wine compares the resolved image's file identity with that target, not its command line or basename, and selects the host only for that image. The host supplies native game-app identity and Game Mode metadata, not policy management. It is an internal explicit-exec host, not a Finder/`open` entry point. Its `argv[0]` remains the canonical ordinary Wine loader so unchanged `loader/main.c` finds the runtime's original ntdll after the bundle-local lookup fails. No adjacent ntdll or external bundle symlink is installed; this path supports the current no-preloader build.

Game Mode no longer selects a window or automatically enters, leaves or re-enters native fullscreen. Windowed and borderless modes retain their normal Wine geometry. If the user explicitly enters native fullscreen, the existing transition callbacks preserve the latest deferred Wine frame and publish AppKit's actual content geometry, including camera-housing insets. An exact geometry echo does not erase a pending frame request. `python3 scripts/test-game-mode-fullscreen.py` executes the production Objective-C methods against synthetic screens, covering windowed focus, borderless frames, manual transitions, geometry acknowledgments and failure paths without changing desktop Spaces.

With the opt-in enabled, the supervisor executes its sibling Apple tool to request a **system-wide** Game Mode override. Native game identity and a global policy status do not prove a per-game scheduling benefit or windowed/borderless policy effect; those effects remain unverified until runtime observation. End-user execution requires neither Xcode nor `xcrun`; the tool is acquired from the selected Xcode installation only when building the runtime. Packaging preserves its original bytes and signature, and the supervisor checks the Apple identity and privileged entitlement before execution. Missing, symlinked or untrusted tools are rejected without searching external developer directories. Policy acquisition failure emits a stderr warning and still runs the game; launch success alone does not prove policy activation.

The lease covers the current Wine session, not an exact game process: after the Wine command exits, the supervisor waits for the supplied `wineserver -w` with the same environment before releasing ownership. Background processes in that Wine prefix can therefore keep the lease alive after the game window closes. Overlapping sessions for the same user share the global lease; the last owner restores the previous auto/on/off policy. The Wine command's nonzero exit status is preserved after server drain. An observed external policy change is preserved, and failed restoration retains a recovery record for the next acquisition. Killing the supervisor itself with SIGKILL cannot guarantee immediate restoration, and an external change to the same forced-on value is not observable. `python3 scripts/test-game-mode-policy.py` covers the session lifecycle with a stateful local backend without changing system policy.

After a complete build/stage, maintainers can validate the host and helpers with `python3 scripts/game-mode.py validate build/staged/wine`. `python3 scripts/test-game-mode-routing.py build/staged/wine` observes native executable paths with a test-only probe while exercising real Wine child creation, aliases, misleading command lines, non-target descendants and missing-host failure; it does not invoke the policy tools. Live QA must observe the actual game's native app identity in windowed and borderless modes, read `build/staged/wine/libexec/yaagl-game-mode/gamepolicyctl game-mode status` during execution, and verify restoration after the Wine session drains. Physical multi-monitor behavior still requires a connected second display.

## Prepare the Apple framework locally

No remote redistributable is assumed. Supply the pristine beta3 framework when building the native preparation bundle:

```sh
node scripts/build-d3dmetal-autopatch.mjs build/d3dmetal-autopatch \
  --framework "$GPTK_FRAMEWORK" --accept-apple-license \
  --sidecar-module build/native-sidecar/libD3DMetalSidecar.dylib \
  --sidecar-manifest build/native-sidecar/build-manifest.json
```

The resulting helper uses a local Apple beta3 disk image and the bundled sidecar:

```sh
build/d3dmetal-autopatch/prepare-d3dmetal-runtime \
  --dmg "$GPTK_DMG" --output build/prepared-d3dmetal \
  --accept-apple-license
```

The helper verifies the input, patch and signatures before publishing output. Disk images are mounted read-only. Direct framework input is also supported with explicit `--framework`, `--license` and `--acknowledgements` paths. Yaagl must obtain Apple license consent before passing the acceptance flag. Preparing local artifacts does not install or replace a live Yaagl runtime.

## Stage a complete local runtime

`GPTK_RUNTIME` is a pristine beta3 Wine graphics distribution containing `lib/external` and the stock PE/Unix graphics modules. It is separate from the Wine host just built. Supply the dependency library directory, GStreamer framework and original native FSR frame-generation DLL:

```sh
python3 scripts/stage-full-wine-runtime.py \
  build/wine-p3-current/host "$GPTK_RUNTIME" build/native-sidecar build/staged/wine \
  --dependency-lib "$DEPENDENCY_LIB" \
  --gstreamer-framework "$GSTREAMER_FRAMEWORK" \
  --native-fg "$FSR_NATIVE_FG_DLL" --accept-apple-license
python3 scripts/stage-runtime.py --verify-runtime build/staged/wine --current-sources
```

The staged launcher uses `yaagl-d3dmetal-runtime.json`, enables Metal4/MetalFX, and selects the RTX 4060 adapter identity. `YAAGL_FSR_UPSCALER=metalfx` selects the translated upscaler; `native` retains the native upscaler while using the packaged frame-generation bridge. The stock NGX pair remains the DLSS route.

Explicit `wineboot` and `wineboot.exe` launches skip optional Mono/Gecko installer dialogs so unattended prefix initialization can finish. This applies only to that process tree, preserves the FSR loader policy, and writes no persistent DLL-disable settings. Ordinary application launches do not inherit these bootstrap-only disables.

`package-wine-p3-runtime.sh` packages the complete local runtime. `package-yaagl-runtime.py STAGED_WINE_ROOT AUTOPATCH_DIR OUTPUT_DIR` instead packages a verified staged runtime with the native preparation helper and omits the Apple framework. The split-package entrypoint uses the same beta3 contracts. Apple framework redistribution remains subject to Apple's license.

## Verification

Run the owner tests for the changed native transport, patcher, preparation helper, staging and launcher. A successful build or CPU fixture does not prove game image quality or FSR frame-generation behavior. Report the exact runtime scenario separately from static and unit checks.

FSR's overhead reductions preserve translation inputs, precision, ownership and history/reset decisions. Pass consolidation uses explicit Metal4 visibility barriers and format-specific GPU comparisons. SR shares its embedded shader library within a feature; FG shares its library and immutable compute pipelines across configurations on the same device within a context, while keeping interpolators and history identities separate. Successful Unix-side API resolution uses acquire/release publication without taking the loader mutex again, while failed resolution remains retryable. FG wakes destruction waiters only on the final closing-context reference and reserves retained-object storage before GPU encoding.

Temporary COM device references use scoped ownership without a shared control block; persistent device ownership is retained. SR reuses the validated output layout. FG reuses mode reads within the configure lock, refreshing after native selection, and preserves an identical HUD-less reference while updating its metadata. Identical scene/present textures share one raw view within an execution. FG packs its constants into one immutable execution-owned buffer, including the offset used for the GPU-written disable hint. SR argument tables travel with execution leases and become reusable only after lease retirement; bounded idle pools support different frames, optional bindings are cleared, and dormant features cannot refill the pools. No live lease shares mutable tables or constant storage.

FG uses one execution-local argument table for all translation passes. Each dispatch snapshots fully refreshed bindings, and simultaneous executions retain separate tables. SR creates only pipelines required by the current operations and depth format, adding others when later frames need them; debug output does not allocate unused normal-finish constants. The transport registers each execution lease against its Metal4 command buffer. A pinned beta3 GPU-completion hook retires only that buffer's leases before the original completion routine's fence notifications and buffer-pool return. Recorded inputs remain allocator-owned for replay; unsubmitted work retains allocator fallback ownership, and partial encoding failures keep their published leases until completion or allocator retirement. The C++ owner state remains embedded in the Objective-C recorded owner.

Metal4 SR batches independent exposure, motion, color and mask preprocessing in one encoder. Generated color padding copies already-converted active edges in that encoder after a dispatch visibility barrier, rather than repeating nonlinear transfer math. Mask generation fills its clamped padding directly. A compatible cached scaler with the exact active input extent takes precedence over an oversized current scaler; absent that cached entry, high-water reuse remains unchanged. Reactivation retains the sequence reset and outstanding-frame ownership. Independent source origins, floating-point precision and Legacy padding remain intact.

Metal4 FG batches baseline copies and preprocessing, with blit-to-dispatch visibility and a fence before MetalFX. R32Float depth/motion normalization shares a dispatch while retaining separate sampling grids, jitter corrections and parameter blocks; other depth formats keep the stored-depth path. Inferred scene/UI decode shares a dispatch with independent origins. Explicit UI composition and final output scatter remain separate.

Each FG context can retain one retired scratch bundle: normalized inputs, generated output, optional inferred UI/distortion, constants, argument table and an emptied residency set. Input snapshots and current/previous scene history are excluded. A live lease owns its bundle exclusively; OFF/DESTROY clears the idle slot, and epochs prevent late retirement or stale replay from refilling it. Native pending-frame metadata and PE configuration snapshots use bounded 64-entry storage without per-frame container allocations. Full IDs, backpressure, newest-preceding configuration lookup and out-of-order retirement are preserved; PE resource releases remain outside the dispatch lock. Texture ancestry is reused only within one dispatch, retaining role-specific mapping and alias rejection.

GPU regressions include 33 bitwise split/fused preprocessing comparisons, generated-padding readback, overlapping leases, configuration changes and OFF/DESTROY retirement. Registry tests cover 64/65 capacity, sparse IDs, failed recording and resource aliases. Generated-output baseline copies and direct-output policy are retained to preserve failure results and pixels. FG Configure validates the request under the state mutex and returns immediately for repeated ON; real transitions and every OFF request retain execution synchronization and cleanup. Regression cases cover repeated ON while encoding is locked and low/high/low SR cache reactivation with an older retained frame.

The native FG regression injects exceptions at the first prepass pipeline binding and at fence finalization on real Metal4 encoders. It submits the partial command buffers and checks baseline pixels, unchanged history, lease retention, scratch retirement and successful retry of the same prepared frame.

FG Prepare and Generate share the input snapshot and its production state; each recorded execution owns its configuration, avoiding a snapshot clone and a separate production-state allocation. R32Float requires only the fused depth/motion pipeline, while other depth formats require the split pipelines. Missing required shaders still reject configuration and can be retried. Named compute texture bindings preserve the existing Metal4 slot clearing and Legacy bindings.

Metal4 FG uses 16x8 threadgroups only for the measured 1920x1080 render to 2560x1440 output profile; other profiles and Legacy retain 8x8. Separate per-context idle slots retain at most one depth snapshot, motion snapshot and scene texture each, with exact device/format/extent/usage matching. Shared owners keep snapshots alive through recorded producers, consumers and execution leases, and keep scene history alive through every writer and previous-history reader. Only the final owner can return a texture; OFF/DESTROY invalidates late returns by epoch.

SR RCAS reuses the center color already loaded by the finish pass instead of reading it again. Neighbor edge clamping, exposure multiplication, sharpening arithmetic, transfer conversion and output alpha are preserved. Native coverage includes translated active crops and centered padding with float32 output, exposure, all transfer functions and sharpness endpoints.

SR returns a completed bundle's scratch resources under one pool lock, after clearing residency, with the same byte cap and eviction order. Within a dispatch, resources whose device pointer matches the validated command device reuse its adapter check; different pointers still undergo the original LUID validation. Regressions cover delayed Prepare execution, shader failures and depth-format transitions, pool caps and dormancy, and device ownership and rejection boundaries.

`python3 scripts/test-fsr-lifecycle.py` exercises concurrent loader publication, failure/retry, the warm fast path, destruction wakeups, temporary/persistent COM ownership and HUD-less replacement/disable behavior. The native SR regression checks retained-lease isolation, retired-table reuse, exposure rebinding, dormant teardown and operation changes against fresh-feature output; the FG regression checks same-texture sRGB output, shared-pipeline lifetime through context destruction, and table isolation across repeated execution with UI and distortion. `node --test scripts/test-native-contract.mjs` exercises the production recorded-owner definitions with controlled backend boundaries, including retain failures, partial/empty encode failures and allocator-retirement teardown. These checks do not establish a measured game-performance gain or whole-game image equivalence.

FG checks Metal4 support once per Prepare/Dispatch invocation before configuration lookup or creation; configuration reuses that same validated command without a second capability query. The support check remains outside the configuration cache, including cache hits. The producer/native regression rejects a missing compiler before and after cache population without consuming pending frames or changing history, then verifies successful retry.

The FG callback-wait guard checks the descriptor type before reading TLS, so ordinary Prepare/Generate calls skip that lookup. WAIT_FOR_PRESENTS remains rejected inside callbacks, and the separate context-specific callback check remains in place. Dispatch regressions cover waiting outside callbacks and rejection inside them, plus ordinary callback Prepare/Generate.

`python3 scripts/test-fg-normalization.py` checks FG dispatch and ownership, plus actual Metal4 motion-texture readback for jitter cancellation.
